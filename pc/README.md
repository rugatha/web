# PC 資料欄位

`pc_lib` 為 JSON 陣列，每筆代表一位冒險者。狀態欄位使用 `true`（是）、`false`（否）、`null`（待確認）；不要將待確認的值當成否。

- `active`：以 `campaign` 中的團務名稱為鍵，表示目前是否仍在該團隊伍中。已結團的團務，以結團時是否仍在隊伍中為準。
- `origin`：以 `campaign` 中的團務名稱為鍵，表示該段團務開始時是否已在本團。
- `dead`：角色是否已死亡，為角色層級的狀態。

跨團角色的 `active`、`origin` 可分別設定，例如以下為格式示意，非角色的實際狀態：

```json
{
  "campaign": ["Rugatha", "Rugatha Plus"],
  "active": {"Rugatha": false, "Rugatha Plus": true},
  "origin": {"Rugatha": true, "Rugatha Plus": true},
  "dead": false
}
```

新增團務關聯時，需同步在 `active` 與 `origin` 加入相同團務名稱。新狀態尚未確認時可用 `null`，確認後再填入布林值。

本次手動狀態表已同步至 `pc_lib` 並移除。依填寫約定，`V` 為 `true`、空白為 `false`；`active`、`origin` 按各團務分別套用，`dead` 則在同一角色任一列有 `V` 時設為 `true`，全部留白時設為 `false`。

## 列表顯示與篩選

`/pc/` 按團務分組，以 `active` 標示隊伍成員／已離隊、`origin: true` 標示初始成員，並以照片角標與邊框標示 `dead: true` 的已故角色。固定／客串玩家依 `guest` 欄位判定，玩家姓名使用 `player` 原名。

預設先展示各團隊伍成員；同一隊伍狀態類別中，存活角色在前、已故角色在後，各自再以初始成員優先；已離隊者收於「過去的夥伴」折疊區，區內同樣優先排列初始成員。未知隊伍狀態保持可見，不視為已離隊。切換語言保留已展開的團務。

「尋找特定冒險者」工具預設收起，展開後提供團務、參與身份、玩家三項常用篩選；隊伍狀態、加入時點、生死狀態放於「更多條件」。六項可交叉使用。主動套用任何條件時，符合結果的已離隊牌卡會自動展開。清除篩選恢復預設折疊瀏覽。

隊伍狀態與加入時點依牌卡所在團務判定，生死狀態則跨團共用；待確認值不視為否。結果分別計算不重複角色數與團務牌卡數，包含折疊區。切換語言保留篩選條件。

牌框使用本地 `legendary-frame.svg` 的簡化暖金拱線，已故角色則使用 `memorial-frame.svg` 冷銀切角框、深藍灰底與較低飽和度的肖像。角色名稱水平置中，底部保留玩家資訊與邊框間距。角色圖片持續以相同比例滿版裁切，各牌卡保持相同尺寸。「過去的夥伴」以整列按鈕、大型加減圖示及展開／收起提示呈現。

篩選邏輯位於 `pc-status.js`，可執行 `node --test tests/pc-status.test.mjs` 驗證。

手機版資訊區縮短高度，隊伍與初始成員標示、玩家與參與身份各保持單行。手機隱藏玩家姓名前綴，英文狀態與身份採短標示；桌面維持完整文字。種族與職業維持分行。

資訊區不再保留固定高度；依目前可見牌卡的自然內容量統一高度，並在篩選、語言切換、展開過去夥伴、視窗寬度或字型載入變動時重新計算，以保持等高並減少底部留白。
