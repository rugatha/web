# Rugatha 管理後台

入口 `/admin/#overview`。本機使用 `http://localhost:8000/admin/`，不可直接以 `file://` 開 HTML。先在同網域／同 port 的既有網站登入；後台僅接受 email 為 `rugathadnd@gmail.com` 且 emailVerified 為 true 的 Firebase 使用者。

## 畫面與資料來源

側欄六個畫面互相獨立，以 hash 路由切換並支援上一頁／下一頁；只有目前分類顯示。

| 畫面 | 資料與行為 |
| --- | --- |
| 管理總覽 | 累計會員、雲端角色卡、NPC、故事弧及章節總量；所選期間新增資料與趨勢。 |
| 團務與章節 | 團務篩選、故事弧搜尋；每個故事弧顯示章節數並可展開連到各章。支援全部展開／收合。 |
| 會員管理 | Firestore `members`；搜尋、排序、每頁 25 筆。名稱連到現有 `/member/?memberId={uid}`；列會員編號、名稱、Email、註冊、最後登入、累計角色卡與答題數，已移除團務欄。 |
| 角色卡 | 逐會員讀取 `members/{key}/characters`；列角色名稱、建立者、會員編號、Email、職業、種族、建立與更新時間。角色連結保留原始 document ID，開啟現有管理員可檢視的角色卡；建立者連到會員頁。 |
| NPC 統計 | 上半段六個圓餅圖顯示全體 NPC 的性別、生存狀態、宗教、種族、所在王國、所在地點；不受下方條件影響。下半段以下拉單選切換特定面向，含分類篩選、分布圖、分類表與分頁明細。 |
| 命運的抉擇 | NPC 目錄題目與逐會員 `qaChoices`；列出 NPC、題目、兩選項完整文字、回答數和各自比例。預設只顯示區間內已有回答的題目，勾選可顯示尚無作答題目。歷史題目保留。 |

左側導覽使用 Rugatha 深綠色與透明底 trademark logo，右側白底黑字，搭配淡綠卡片與深綠區塊標題。管理用語直接描述數量、篩選與口徑。

## 日期與統計口徑

- 日期統一置於右側最上方，跨畫面保留並套用所有受時間影響的資料。日期最早固定為 2026-01-01；預設 2026 年起至今天。起訖欄位、雙滑桿與近一週（7 天）／近一月（30 天）／近一年（365 天）快捷鍵皆受此下限限制。包含台北時間起訖兩天，以結束日次日 00:00 作排除上界。
- 日期變更只重算已讀資料，不重新請求 Firebase。資料在頁面載入時讀取一次；已移除「更新資料」按鈕，需要新資料時重新載入網頁。無效、早於 2026-01-01、顛倒日期或晚於今天的結束日不套用。
- 會員可依註冊時間或最後登入時間篩選；角色卡可依建立或更新時間篩選；NPC 作答依 createdAt。網站靜態目錄無時間欄位，NPC 與團務不受日期影響；頂部統一日期控制維持顯示並標明適用範圍。
- 總覽累計指標不受日期影響。最後登入 KPI 使用全體會員的 lastLoginAt，代表最後登入落在區間的人數，不代表區間歷史活躍會員、登入次數或工作階段。
- 趨勢圖排除未記錄建立時間的紀錄，90 天以內逐日彙整，較長期間逐月彙整。未記錄時間的資料不列入日期區間。累計總數與期間清單可能不同；清單摘要明確說明排除未記錄時間的資料。
- NPC 多宗教、多種族或多地點：每位 NPC 在同一分類最多計一次，不同分類可重複計入。分母是符合篩選的 NPC 數，占比總和可能超過 100%。未註明不可解讀為沒有信仰等。
- 所在王國依 `map/location/assets/location.json` 的中英文地點階層對應，排除草稿地點；不能對應則標「未能對應」，不推斷國籍或出生地。
- 2026-10-25 核對正式 Firebase：18 筆回答、9 位會員，其中 17 筆舊紀錄 createdAt=null，1 筆有 Timestamp。後台預設納入未記錄日期的歷史回答，並顯示累計、區間內有日期、日期未記錄的三種數量；可取消勾選只看區間內有效日期。日期未知的回答不擅自指派時間、不宣稱屬於所選期間。總覽期間答題數維持只計日期已知，另列無日期歷史筆數與查看連結。
- 命運抉擇：比例＝該選項回答數 ÷ 同題 C1+C2 回答總數；未作答比例顯示「—」。會員人數去重，答題筆數與人數分開。僅含 NPC 二選一題，不含團務章節問答；無目前題目文字的歷史作答保留統計。
- 角色卡只包含 Firebase 雲端儲存，不包含網站 PC 文章或瀏覽器單機資料。每筆角色卡以所屬會員路徑連結建立者。
- 任一會員子集合讀取失敗，該類總量與清單不顯示，避免把部分結果當總量；失敗與零筆明確分開。讀取每批最多 8 位會員，單次請求超時為 20 秒。

## 表格操作

會員、角色卡、NPC 明細、NPC 分類表與命運抉擇共用 `admin/data-table.js`。欄名按鈕可切換升冪／降冪，欄下直接篩選：文字包含、分類單選、數值上下限、日期起訖。所有欄位條件取交集，先篩選與排序整份資料，再分頁；沒有符合資料時仍保留欄位控制，方便恢復。

拖曳欄位把手可換序，也可用 Alt＋左右方向鍵移動。僅欄位順序保留於當前瀏覽器 localStorage，不保存表格資料或篩選文字；可清除欄位條件與還原欄序。欄位條件會同步更新該表格對應的篩選後 KPI；NPC 下半段以明細篩選結果重算分布，上半段仍為全體 NPC。

NPC 圓餅圖使用分類人次作分母，多值欄位可一人多分類；單值面向等同 NPC 人數。過多分類合併為「其餘 N 個分類」，避免難以辨識的小切片。下半段則維持各分類占符合 NPC 人數的比例，兩者分母均有標示。

## 靜態目錄

`admin/catalog.json` 由 `scripts/build-admin-catalog.mjs` 從共用團務設定、故事弧／章節標題和實際 HTML 產生。只計實際 index 與章節檔案；單篇傳奇算一章。每個故事弧內含 chapterList（標題與 URL），不由沒有下一章推斷故事弧完結。Pages 部署前自動重建；本機使用 `npm run admin:catalog`。

## 存取與流量功能狀態

未登入／錯誤帳號／未驗證信箱／登出會清除資料並轉往不存在的 `/404/`。GitHub Pages 無法按 Firebase 身分控制第一個 HTTP 回應；初始 HTML 只有公開空殼，資料須通過 Firebase Auth 與 Firestore Rules。若要求初始請求就回 404，需驗證伺服器 session 的服務。

開檔、模組載入失敗或驗證超過 20 秒會顯示可恢復的提示，權限未完成時不顯示資料。會員與子集合沿用既有 isAdmin 規則；本次未擴大會員資料權限。

2026-10-25 依使用者要求移除 page access：已移除畫面、Firebase 查詢及 shared/auth.js 的追蹤呼叫，並撤回已部署的 `pageAccessEvents` 規則。所有客戶端（包括管理員）均不可再讀寫這個集合；既有紀錄未刪除。Firebase 已部署停止流量存取的規則；網站透過本倉庫 main 分支的 GitHub Pages 工作流程發布。

## 驗證

```sh
npm run admin:check
npm run test:catalog:setup
npm run test:rules
node --test tests/image-pwa.test.mjs
RUGATHA_IMAGE_TEST_PORT=8790 node scripts/image-browser-server.mjs
# 另開 shell：
node tests/admin-dashboard.browser.mjs
```

規則模擬器需 Java 21 以上，瀏覽器測試需 Chrome。模型單元測試涵蓋台北起訖邊界、錯誤日期、多值分類分母、王國對應、未作答與歷史題目、長期間彙整及建立者連結。瀏覽器測試涵蓋六畫面切換、日期拖拉、會員分頁、明細連結、折疊章節、六種 NPC 面向、題目與比例、未授權 404、載入失敗／逾時和手機寬度，並確認不查詢流量。

瀏覽器測試僅在測試程序中攔截 Firebase SDK，正式程式沒有預覽身分繞過。`output/admin/v4-*.png` 是標明測試資料的版面截圖，不納入版本控制；實際登入的本機網站讀取正式 Firebase。
